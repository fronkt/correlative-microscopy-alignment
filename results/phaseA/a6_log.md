# A6 log: burned-in overlay audit over all 187 eval pairs (exploratory; nothing here is confirmatory)

Script: `scripts/phaseA_a6_overlay_audit.py` (`PYTHONPATH=src`; about 80 s for the audit; `--pilot` runs the SIFT pilot, about 3 min). Outputs: `a6_overlay_audit.json`, `a6_per_image.csv` (156 distinct images), `a6_per_pair.csv` (187 pairs), `a6_candidate_rows.csv` (2,805 voting rows, core+transform pools), `a6_thumbs/`, `a6_sift_pilot.csv/json`.

## Pair -> image mapping
`AmalgaMatchLoader.records` (built from the eval_indexs npz `image_paths` / `pair_infos`) gives source_path / target_path per pair; the 187 pairs use 156 distinct image files. Files opened with the `\\?\` long-path prefix (`_long_path`), decoded with `cv2.imdecode`; 16-bit images stretched to uint8 on the 0.5-99.5 percentile, colour/RGBA to grey.

## Detectors and thresholds (final)
- BAND (data bar / metadata banner), tested on all four edges, working image = long side <= 3072: a line is band-like if >= 50 % of its pixels lie in the modal +-1 bin (32 grey bins), an "anchor" line if >= 90 %. Band = contiguous band-like run from the edge (gap <= 3 lines), trimmed to end on an anchor line, depth 6 px to 12 % of the dimension. Inside, glyphs = connected components (8-conn) of |pixel - band median| > 50, area >= 6 px and <= 2 % of band, height 5 px .. band height. Accepted only if >= 20 glyphs, >= 70 % of glyph heights within +-40 % of the median, and >= 75 % of glyph centres inside the best two text lines (+-0.6 median height).
- LABEL (scale-bar caption in a corner), 30 % corner windows: (a) boxed: saturated (>= 250) rectangular component, width 2-20 % / height 1-15 % of the image, aspect 1.5-8, fill >= 0.4, >= 2 interior dark holes, within 8 % of both nearest edges; (b) free text: >= 3 saturated glyph components of uniform height (+-40 %), on one line, within 15 % of image width, within 8 % of both edges.
- Pair level: SHARED_OVERLAY = both images flag the same band edge or the same label corner. SHARED_FIXED = SHARED_OVERLAY and identical image size and (band height fractions within 1 % or a shared label corner). Also recorded: identical-pixel fraction of the band rows (|diff| <= 8) for same-size pairs (0.87-0.90 for the TEM bands; the residue is the detector label and the dwell/scale text).

## Variants tried (all of them)
1. v1: band flat threshold 0.60, glyph rule = >= 8 small components, depth cap 25 %. 78 images flagged; the whole-set contact sheets (156 tiles, viewed) show at most about 37 real overlays. False positives: black margins with speckle (In718 Slice30/60/90/120, BSE_xxx, EBSD maps), and the HAADF STEM banners were truncated to 0.9-1.1 % height (text rows only ~0.6 modal fraction), so 14 TEM pairs lost SHARED_FIXED.
2. v2: flat 0.50 with an anchor-line end rule, glyph height >= 5 px, uniform-font and text-line tests, min 8 glyphs. 42 flagged. Remaining false positives: In718 Slice30-120 (black margin 22 % deep), Confidence_index (dark fringe, 3.6 %), BSE_450 top_left "label" (a small bright rectangle inside a saturated sample).
3. v3: depth cap 12 % (all true bands are 6.6 % or less), min glyphs 20, min uniform 0.70 (155 had uniform 0.60, 10 glyphs; true bands had >= 0.73, >= 77 glyphs), label box must lie within 8 % of a corner. 36 flagged.
4. v4 (final): added the free-text corner caption (C103 sample12 composition "50 um", white text with no box; missed by v3, found by eye in a corner crop). 37 flagged: 29 STEM banners, 3 C103 SE2 SEM data bars, 5 corner scale-bar captions (C103 composites/height maps: images 22, 24, 27, 29, 30), image 28 also carries a corner hit (its data-bar logo).
The thresholds of variants 2-4 were tuned on these same images, so the validation below is in-sample, not a held-out test. Not covered by design: small-object marks inside the field of view. TRIP1 corner triangles and the pyramid marks in the Ta/TRIP1 composites are physical hardness indents, not burned-in overlays, and are not flagged (checked by eye at full resolution).

## Results
Images with overlay: 37/156.
Pairs (187): SHARED_OVERLAY 67, SHARED_FIXED 66 (only pairs with same image size are 66, all of them the three MoTaTiZrHf TEM subsets; the C103 shared pair is a label-only match with different sizes).
- DislocationCharacterization: 66/69 shared (32 + 16 + 18 MoTaTiZrHf; Ti3AlC2 3 pairs: no banner). FractureSurfaces 1/6. Multiscale, SameSlice, SerialSectioning, SlipPartitioning 0.
- Every same-size pair in the benchmark is a banner pair, and every banner-shared pair except the one C103 pair is same-size. So overlay, same size and "identity is a possible-looking answer" are perfectly confounded; the only overlay-free control is Ti3AlC2 (3 pairs, GT shift about identity, MA-RoMa errors 1.3-2.0 px, succeeds).

Near-identity failures (NEAR_IDENTITY_FAIL = H within 20 px of identity on the 5x5 target grid, error > 20 px incl. failed runs, GT displacement > 40 px; GT displacement = gt homography row vs identity, GT displacement in shared pairs 54-511 px):
- All 2,805 voting rows (core+transform pools): 2,315 failures, 490 near-identity, 475 NEAR_IDENTITY_FAIL (20.5 % of failures). 475/475 are in SHARED_OVERLAY pairs (all SHARED_FIXED, all same-size); 0 in pairs without a shared overlay. By backbone: SIFT 66/187, LoFTR 40/187, MatchAnything 65/187, RoMa 117/1122, MA-RoMa 187/1122; all in shared pairs. By group: DislocationCharacterization 475, every other group 0.
- MA-RoMa direct seed 0 (187 rows): 143 failures, 36 near-identity, 35 NEAR_IDENTITY_FAIL = 24.5 % of its failures; all 35 in shared pairs (61 of 67 shared pairs fail, 91 %; NIF explains 57 % of those; the other 26 failures are not identity locks). DislocationCharacterization non-shared pairs (Ti3AlC2) fail 0/3.
- Near-identity locks without shared overlay: 0 NEAR_IDENTITY_FAIL. There are 15 near-identity rows in overlay-free pairs but all are near-identity successes (GT displacement 1-20 px, errors <= 14 px; Ti3AlC2 and one Multiscale row), which are legitimate. So there is no other cause of a near-identity lock in this benchmark.
- Failures that are not identity locks stay large: 1,840 of 2,315 failure rows.

S1 (MA-RoMa direct seed 0, cutoff 0.1711 recomputed on SameSlice+SerialSectioning) over all 187 pairs: 89 accepted, 50 false accepts (42 held-out DislocationCharacterization + 8 in the two design groups: SerialSectioning 4, SameSlice 4). 29 of the 50 (58 %; 29 of the 42 held-out = 69 %) are near-identity locks in shared-overlay pairs (all 29 SHARED_FIXED; 15 in 1100C, 13 in 900C largeFOV, 1 in 900C). The other 21 false accepts: 13 are shared-overlay TEM pairs that are not identity locks (near misses and off-identity errors), 8 have no shared overlay (the 8 design-group false accepts; 0 in overlay-free non-design groups). This matches A1 (29/42 within 20 px of identity).

## Caveats
- Detector thresholds were tuned in-sample on the 156 images; precision/recall of 1.00 is therefore optimistic.
- SHARED_OVERLAY, same image size and TEM modality are the same 66 pairs, so the audit shows association (all 475 locks are in these pairs) not a causal proof for the dense matchers; the causal test exists only for SIFT (A1 and the pilot).
- Near-identity is measured on the 5x5 grid of the target image, in source pixels.
